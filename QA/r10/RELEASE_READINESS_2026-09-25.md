## Launch blockers and priorities

1. **P0 — closed-app worker phone notifications absent.** A `notification_preferences.push` boolean exists (one of eight inspected Savanna preference rows true), but there is no web service worker push handler or registration, device subscription and permission flow, VAPID configuration, notification fan-out/sender, delivery retry/observability, or enrolled device test. Current inbox delivery only works while using the app; the new source Realtime invalidation accelerates the open staff app. Do not promise lock-screen notifications. Implement private, recipient-scoped Web Push and test foreground, background, killed browser, Android, and installed iOS Home Screen behavior; configure an explicit fallback for urgent worker tasks.
2. **P0 — security and money workflows remain open.** Live recheck on 25 September supersedes the older register: four scheduled maintenance routines now deny both `authenticated` and `anon` EXECUTE. The live database has canonical sync triggers for both folios and purchase orders, but **70 of 100 folios** lack a `folio` canonical record, and **3 of 28 purchase orders** lack a `procurement` canonical record. Do not interpret the 28 as missing merely because their source module is `procurement`. Review missing historical rows with Finance before backfill, then verify reconciliation. Other privileged routines still require function-by-function review and role testing; some RBAC-07 examples already have guards or revoked grants. The master register is a historical lead, not a reliable current-status tally.
3. **P0 — outbound messaging and payment have no production proof.** Live published source includes `communication-providers.server.ts` with Resend, Africa's Talking and WhatsApp adapters; the old register's “no sender exists” finding is obsolete. On 25 September the live queue had **438 queued rows** (421 email, 17 SMS), **zero** delivery-event rows, including **408** inventory daily reconciliation emails and **17** delivery SMS messages dated as far back as 14 September. `is_test=false` is set even for some QA tenants, so that flag cannot safely release the queue. R11 local source adds an outbound fail-closed gate requiring `NEO_OUTBOUND_ENABLED=true` and a reviewed `NEO_OUTBOUND_CUTOFF`; records older than the cutoff are retained for review and cannot auto-send. Do not enable a scheduler or credentials against the historical backlog. Provider acceptance, delivery and real payment callback remain unproven.
4. **P1 — full frontend journey evidence incomplete.** Test on actual phones and desktop across guest sign-in/booking/checkout/payment, worker assignment/acknowledgement, POS/kitchen/folio/finance, procurement/store, housekeeping, maintenance, rider delivery, accessibility, slow network, error and retry, logout and property switching. Capture screen/video, role, tenant, record IDs and backend transitions. Static inventory and unit tests cannot establish this.
5. **P1 — public menu content was exposed.** Four published Zuri RUN2 dishes and seven published Savanna Nairobi `CERT` dishes were moved to `draft` by exact tenant/branch and item match. No order, menu item, stock, or history records were deleted. A follow-up count for these published names was zero in those branches. Review remaining published tenant content before public promotion.
6. **P1 — source UX fixes require deployment.** R10 source now hides Zuri home dining actions when no published room-service items exist; guest checkout refreshes folio while awaiting provider settlement and offers a retry on bill load failure; reservation date defaults use browser calendar date; staff inbox badge resyncs with Realtime; and the Push setting is disabled with an honest explanation. None is proven on the live site until promoted and retested.
7. **P1 — personal phone push source requires deployment and setup.** R11 source adds worker service worker, self-owned subscription RLS, per-device delivery queue, a protected sender with retries, and a rate-limited test alert. This reaches only notifications with an explicit `user_id`; property, department and station audiences still need rights-preserving fan-out. Requires VAPID keys, 32+ character dispatcher token, HTTPS scheduled POST, migration, deployed browser code, and Android/iOS real-device verification. Provider acceptance alone is not phone receipt.

## 25 September continuation (R11 source)

- The live privilege census found 698 callable SECURITY DEFINER functions for `authenticated` and initially 35 for `anon`; those are surface counts, **not** 698 proven exploits. Sixteen staff or signed-in guest functions were granted anonymous EXECUTE. Their exact grants were revoked live and verified `anon=false`, `authenticated=true`, with an idempotent migration included. The remaining anon-callable SECURITY DEFINER count is **19**. The hardened manifest check also exposed a broken `/kitchen/settings` reader: `neo_station_store_readiness` had `authenticated=false`; its org/branch-scoped read was granted to `authenticated` and verified `anon=false`. This fixes a server grant, but the screen still needs a signed-in role journey.
- The live queue contains 438 queued messages and zero delivery-event rows. No mass dispatch was run. The local sender now fails closed without an explicit enabled switch and reviewed creation-time cutoff. The automation dashboard source displays the hold state.
- New personal Web Push infrastructure is **source-only**. `worker_push_subscriptions`, `worker_push_deliveries`, an opt-in control, generic-payload service worker, signed test alert and protected dispatch endpoint are included, but the migration and browser/server code are not live. Opt-in and dispatch are off by default until a configured scheduler is explicitly enabled. It does not target department/station/property notifications, and no VAPID keys or scheduler are configured. Do not claim phone delivery until a device receives a locked-screen test in production.
- Live Zuri guest Explore → Services → Make a request navigated to the signed-out stay gate; no private request was exposed.
- Attempted the hosted project editor to apply prepared UI fixes. It returned **workspace out of credits**, so there is no new Lovable commit or published revision. Do not run deployment against the unchanged hosted source and call the local changes live.
- `vite preview` seeks a nonexistent `dist/server/server.js` under this Cloudflare build; `nitro preview` could not start Wrangler here because the runtime could not enumerate network interfaces. The project's build smoke check passes, but the new push endpoint's Cloudflare runtime path remains unproven until a deployed-worker test.

## Release gate

Hold public launch until security privileges and finance state are verified, external sends and payments demonstrate real provider evidence, push is either fully delivered on devices or clearly excluded from promised worker operations, and named role sessions complete the full cross-role journey matrix. Promote source changes, then repeat live browser/device and database checks against the deployed revision.
