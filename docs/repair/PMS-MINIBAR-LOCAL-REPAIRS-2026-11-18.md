## Durable Minibar requests and ownership

- `20261118110000_minibar_durable_attempts.sql` stages the guarded existing posting engine plus `neo_minibar_post_once(uuid,uuid,jsonb,uuid,text,uuid)`. Unknown engine/wrapper bodies or an unexpected request-table schema stop installation. Existing engine grants/owner are preserved; the private request table and wrapper use its trusted owner. Direct table access is revoked from ordinary client roles.
- A UUID request identity binds the original payload and saved result. Exact retries return the original posting without another charge, stock deduction or document number, including after checkout. Changed drafts under that identity are refused. Missing/changed saved posting evidence requires reconciliation.
- The old five-argument routine refuses unkeyed direct posting after installation. A private pending row matching the caller, folio, room, store and payload is required; merely setting a custom transaction flag is insufficient.
- New charges require an active store with explicit `location_type='minibar'`, in the folio's property. No inference from store name, Bar mapping or a departmental mini-store flag is made. Inventory configuration now offers this explicit store type. Existing configuration requires review; no store is renamed or reclassified automatically.
- The room must belong to the folio's current in-house stay, reservation, organization and property. The client displays the stay's room rather than an older reservation-room value.
- The engine uses the four-argument organization-scoped `next_document_number` explicitly, avoiding the overlapping older numbering signature. Posting failure rolls back its issued reference with the other database effects.
- The browser retains only the request UUID, scoped by organization/employee/folio; guest details, notes and draft lines are not persisted by this helper. Secure Web Locks serialize request-key creation between tabs. An uncertain result retains the draft and identity; success also retains the identity until **Start a separate charge** is explicitly confirmed. Switching folios or remounting does not silently rotate the saved identity. Unavailable secure storage prevents dispatch.
- Posting history can be filtered to the selected folio, and its folio identity is displayed. A missing new RPC produces an installation-required error; the client never retries through the unkeyed legacy command.
